# 2026-07-14 工作日志

## 排查 m.suyuank.top/post/4824 返回 500 Internal Server Error

- 用户反馈 `https://m.suyuank.top/post/4824` 直接打开报 Internal Server Error，怀疑是安全设置导致。
- 结论：**不是安全设置问题**。500 是服务器端代码异常，CSP/CORS/HSTS 等安全头只在响应正常返回(200)后由浏览器层面拦截资源，不会让服务器自己返回 500。
- `/post/4824` 路径匹配 `src/index.js:88` 的 SPA 路由正则 `^\/post\/[^/]+\/?$`，应返回 Vue 前端 index.html。
- 关键嫌疑点：`src/index.js:229-233` 的全局中间件对每个请求执行 `db.init()`，其中 `src/db.js` 的 `CREATE TABLE` 语句没有 try/catch 包裹，D1 binding 异常或暂时性故障会直接抛 500。
- 优化建议：`db.init()` 不应每个请求都跑，应移到 `scheduled` 或一次性迁移脚本；或给 CREATE TABLE 也加 try/catch；并给 app 加 `onError` 输出异常堆栈方便定位。
- 排查命令：`npx wrangler tail` 实时查看 Worker 异常堆栈。

## 定位到真实根因并修复 /post/4824 的 500 错误

用户补充关键现象："首页点击进去正常，新开页面直接访问报 500"。结合 Cloudflare 文档确认：

**Cloudflare Workers Static Assets 默认 `run_worker_first = false`**：
- 请求匹配到静态文件 → Assets 直接返回，**Worker 不执行**
- 请求不匹配静态文件 → fall through 到 Worker

三个场景的行为差异：
| 场景 | 行为 | 结果 |
|------|------|------|
| 直接访问 `/` | Assets 找到 index.html 直接返回，Worker 不执行 | 正常 |
| 首页点击进入文章 | Vue Router createWebHistory 客户端导航，不发 HTTP 请求 | 正常 |
| 直接访问 `/post/4824` | Assets 找不到文件 → fall through 到 Worker → Worker 抛异常 | 500 |
| API `/api/posts/4824` | 经过 Worker 但匹配 API 路由，不进入 app.all('*') | 正常 |

**真实根因**：`src/index.js` 的 `app.all('*')` 中，对 `c.env.ASSETS.fetch()` 返回的 Response 直接调用 `response.headers.set('Cache-Control', ...)`。ASSETS.fetch 返回的 headers 是 **immutable（不可变）**，调用 set 会抛 `TypeError: Can't modify immutable headers`，Hono 默认错误处理返回 500。

**修复**：把 `new Response(response.body, response)` 移到设置 Cache-Control 之前，先创建可变副本 `secured`，再在 `secured.headers` 上 set。已修改 `src/index.js:255-271`。

**关键教训**：Cloudflare Workers 中 fetch()/ASSETS.fetch() 返回的 Response headers 是 immutable 的，修改前必须 `new Response(old.body, old)` 创建副本。
